# ORBIT 여행 플래너 인수인계

작성일: 2026-11-14 · 코드와 로컬 산출물 기준 · 다음 개발 담당자 및 제품 담당자용

## 1. 먼저 알아둘 내용

ORBIT는 해외 도시의 2D·3D 지도를 보며 날짜별 방문 일정을 만드는 웹 시제품이다. 기본 도시는 후쿠오카다. 여행 편집, 직접 장소 추가, 백업, 당일 보기와 인쇄 화면까지 구현되어 있다. 실제 장소 검색·실제 길찾기·계정 저장은 연결되지 않았다. 이동시간은 예시값이고 지도 점선은 방문 순서 연결선이다.

**이번 인수인계에는 원본과 미반영 개선 작업본을 함께 제공한다. 두 버전을 혼동하지 않는 것이 가장 중요하다.** 이번 문서 작성 과정에서 원본 프로젝트나 웹사이트를 수정·재배포하지 않았으며, 사용자 브라우저의 여행 데이터도 읽거나 변경하지 않았다.

| 구분 | 묶음 안 위치 | 의미 |
|---|---|---|
| 기준 코드 | `baseline/` | 원래 프로젝트 폴더에 현재 저장된 코드의 복사본 |
| 개선 후보 | `candidate/` | 저장 실패·손상 자료·다른 탭 변경 보호를 추가한 작업본. 원본 반영·배포 완료로 간주하면 안 됨 |
| 기존 문서 | `reference/` | 이전 기획서·화면설계서·작업기록과 게시 주소·QR |
| 검증 증거 | `evidence/` | 이번에 실행한 테스트 결과와 파일별 SHA-256 목록 |

원본 위치: 작성자의 로컬 프로젝트 폴더(비공개)

개선 후보 출처: 별도 작업공간의 `orbit-stability/`.

기록된 공개 주소: (비공개 처리)

이 주소는 기존 게시 기록에서 확인했다. 2026-11-14 현재 서비스 접속 여부·원격 배포 버전은 재확인하지 않았다. `reference/호스팅체크아웃-스냅샷.html`은 로컬 `orbit-site/dist/index.html`의 사본일 뿐 현재 원격 배포본이라는 증거가 아니다. 개선 후보의 단일 HTML과 이 파일의 해시는 서로 다르며, 기준 코드의 단일 HTML(`baseline/outputs/ORBIT-인터랙티브-시안.html`)과는 SHA-256이 같다. 즉 로컬 체크아웃은 기준 코드 상태이고, 마지막 배포가 이 체크아웃에서 이뤄졌다면 원격도 기준 코드일 가능성이 높다(원격 직접 확인은 아님).

## 2. 처음 받은 사람이 실행하는 순서

1. `baseline/outputs/ORBIT-인터랙티브-시안.html`을 브라우저에서 열어 기능을 살펴본다.
2. 코드 수정은 `baseline/work/travel-globe/dist/prototype/`에서 시작한다. 저장 안정성 작업을 이어받으려면 같은 구조의 `candidate/`를 사용한다.
3. 두 버전을 같은 브라우저·같은 주소에서 번갈아 시험하지 않는다. 저장 공간이 겹칠 수 있다. 별도 테스트 프로필 또는 서로 다른 로컬 포트를 사용한다.
4. 사용자 일정으로 시험하지 말고 시험용 여행을 만든다. 실제 데이터 이전이 필요하면 원래 주소에서 JSON 백업부터 확보한다.
5. 아래 자동 테스트 후 실제 Android 화면과 저장 실패 상황을 검토한다. 후보 승인 이후에만 원본 반영과 배포를 진행한다.

지도 라이브러리·지도 배경·글꼴은 인터넷 연결이 필요하다. HTML 하나로 제공되지만 완전한 오프라인 앱은 아니다. 파일 열기 방식의 브라우저 저장 동작은 환경마다 다를 수 있어 개발 검증은 로컬 서버를 권장한다.

## 3. 구현된 기능과 한계

| 기능 | 현재 동작 | 주의점 |
|---|---|---|
| 여행 생성·수정 | 이름·도시·출발일·도착일, 최대 14일, 날짜 미정 | 여행 하나당 도시 하나 |
| 여러 여행 | 브라우저 저장, 삭제 보관과 복원 | 계정·기기 간 동기화 없음 |
| 장소 검색 | 도시별 예시 목록에서 이름·지역 검색 | 전체 장소 검색 API 아님 |
| 직접 장소 추가 | 이름·주소 또는 위치 메모·방문 날짜 입력 | 좌표 없음. 위치 미등록 안내, 지도 핀 없음 |
| 방문 편집 | 순서·날짜·체류시간·고정 시각·방문 메모 | 같은 장소를 여러 번 방문 가능 |
| 기간 단축 | 줄어드는 날짜의 방문을 마지막 날 이동 또는 미배정 보관 | 미배정 장소는 날짜 선택 후 재배정 가능 |
| 숙소 | 이름·주소 메모 | 숙소 좌표와 출발·도착 경로 미구현 |
| 시간표 | 체류와 예시 이동시간 합산, 충돌·미확인 안내 | 실제 교통편·거리·영업시간을 조회하지 않음 |
| 지도 | 2D·3D, 예시 장소 핀, 순서 연결선 | 좌표 없는 방문 전후를 건너뛰어 연결하지 않음 |
| 당일 보기 | 도시 현지 날짜·일자 이동·방문 정보·메모 | 여행 기간 밖이나 날짜 미정이면 선택 날짜 안내 |
| 인쇄 | 전체 여행/하루, 메모 포함 여부, 인쇄 전용 화면 | 실제 PDF 출력·페이지 분할 최종 검증 필요 |
| 텍스트 내보내기 | 일정·메모 등 텍스트 다운로드 | 복원용 포맷이 아님. 미배정 직접 장소 주소 누락 검토 필요 |
| JSON 백업·복원 | 여행·방문·숙소·직접 장소·미배정·삭제 보관 포함 | 기존 여행에 사본 추가. 반복 복원하면 중복 생성 |

예시 도시: 후쿠오카, 도쿄, 오사카, 파리, 런던, 뉴욕. 실제 서비스 지원 도시로 확정된 목록은 아니다.

## 4. 코드 구조

프레임워크 없이 HTML·CSS·일반 JavaScript로 구현했다. Node.js는 테스트·로컬 서버·단일 HTML 생성에 사용한다. 이번 검증 실행 환경은 Node.js v24.18.1이며 최소 지원 버전은 별도 확정하지 않았다.

| 파일 | 역할과 수정 지점 |
|---|---|
| `index.html` | 기본 화면, 입력 폼, 모달, 지도 영역, 스크립트 로딩 |
| `style.css` | 화면 스타일, 모바일 대응, 인쇄 전용 스타일 |
| `destinations.js` | 도시와 예시 장소, 좌표·카테고리 |
| `core.js` | 날짜 계산, 시간표, 기간 변경, 직접 장소 검증, JSON 백업 검증·생성·추가 |
| `app.js` | 앱 상태, 저장, 화면 갱신, 검색·편집 이벤트, 지도, 내보내기 |
| `day-view.js` | 현지 날짜 계산, 당일 카드, 인쇄 HTML·미리보기 |
| `work/package_prototype.cjs` | 소스 6개를 출력 폴더에 복사하고 CSS·JS를 포함한 단일 HTML 생성 |
| `work/preview-prototype.cjs` | `127.0.0.1:4173` 로컬 미리보기 서버 |
| `work/test-*.cjs` | 계산·백업·메모·직접 장소·날짜·당일 보기 등의 자동 검증 |

스크립트 순서: MapLibre → destinations.js → core.js → day-view.js → app.js. 전역 함수·상태를 공유하므로 로딩 순서와 함수 이름 변경 시 함께 검토해야 한다. 화면은 HTML 문자열과 이벤트 처리로 구성하며 사용자 텍스트 출력에는 `esc()` 이스케이프를 사용한다.

외부 의존성: MapLibre GL 5.6.1(unpkg CDN), OpenFreeMap 지도 스타일·타일, Google Fonts Noto Sans KR, 좌표 기반 외부 Google Maps 링크. 비밀 API 키나 로그인 서버는 이 소스에 필요하지 않다. 외부 자원의 가용성·이용 조건·출처 표시는 향후 운영 전에 검토한다. 현재 요금이나 이용 조건을 이번 인수인계에서 확인한 것은 아니다.

## 5. 데이터 구조와 호환성

브라우저 저장 키: `orbit-interactive-prototype-v1`. 최상위는 `{trips, active, three}`다. 저장은 웹 주소의 출처(origin)에 종속된다. 로컬 파일·로컬 서버·공개 사이트·다른 기기는 같은 저장 공간이 아니다.

| 객체 | 주요 필드 |
|---|---|
| 여행 | `id`, `name`, `city`, `date`, `days`, `hotel`, 선택적 `customPlaces`, `unassigned`, `deletedAt` |
| 하루 | `start`, `mode`(walk/transit), `scenario`(normal/failure), `visits` |
| 방문 | `uid`, `place`, `duration`, `fixed`, 선택적 `note` |
| 직접 장소 | `id`(custom- 접두어), `name`, `address`; 표시 시 `coord:null` |
| 미배정 방문 | 방문 필드 + `originalDay` |
| 숙소 | `null` 또는 `{name,address}` |

장소 ID와 방문 UID는 구분해야 한다. 같은 장소의 반복 방문 메모·시간은 각각 다른 방문에 저장된다. 직접 장소 정보는 여행에 속하며 방문이 해당 ID를 참조한다.

백업 봉투는 `{format:'orbit-travel-backup', version:1, createdAt, trips}`다. 복원은 여행·방문 ID를 새로 부여해 기존 여행 뒤에 추가한다. `customPlaces`가 없는 이전 백업도 허용한다. 직접 장소가 포함된 새 백업은 이전 앱에서 복원되지 않을 수 있으므로 최신 앱을 사용한다.

현재 백업 검증 제한: 5MiB(5×1024×1024바이트), 여행 1,000개, 전체 방문 10,000개(미배정 포함), 여행별 직접 장소 최대 10,000개, 여행 기간 1~14일. 방문 메모 최대 1,000자, 체류 5~720분. 장소 이름 80자·주소 300자, 여행 이름 60자, 숙소 이름 80자·주소 200자 제한이 있다.

**검토할 경계:** 앱의 누적 데이터가 백업 제한을 넘으면 백업 생성 자체가 실패할 수 있다. 후보의 로컬 읽기는 일부 백업 크기·개수 제한을 완화하지만 내보내기 제한은 그대로다. 데이터가 늘기 전에 사전 안내, 여행별 백업 또는 분할 백업이 필요하다.

## 6. 저장 안정성 후보 작업의 인계

기준 코드와 다른 파일은 `index.html`, `style.css`, `core.js`, `app.js`다. `destinations.js`, `day-view.js`는 두 버전이 동일하다. 후보에 `test-storage-stability.cjs`를 추가했다.

- 저장 실패를 지속적으로 안내하고, 추가·삭제·순서 변경·숙소·일자 설정 등의 실패한 변경을 되돌린다.
- 여행을 열기만 할 때 전체 자료를 다시 저장하지 않는다.
- 로컬 자료가 깨졌거나 ID가 중복된 경우 일부 자료만 남겨 덮어쓰지 않고 저장을 막는다.
- 읽을 수 있는 원문을 `ORBIT-저장원본-복구용.json`으로 보관할 수 있다. 일반 백업과 포맷이 달라 일반 복원 메뉴에 넣으면 안 된다.
- 저장 직전에 원문을 비교해 다른 탭의 변경을 발견하면 저장을 중단한다. 원자적 잠금이나 완전한 동시 편집 해결책은 아니다.
- 장소 조회를 Map으로 캐시하고 백업의 장소 ID 검증을 Set으로 처리한다.

후보에 필요한 최종 확인: 실제 브라우저의 저장 용량 초과·저장 차단 UI, 두 탭 수정 경쟁, 손상 자료 복구 안내, 입력창 보존, 기존 데이터 호환성. 실제 화면 검증·원본 반영·웹 배포가 끝났다는 증거는 확보하지 못했다. 이번 문서 작업에서는 자동 테스트만 재실행했다.

## 7. 실행·테스트·패키징

아래 명령은 선택한 버전의 루트(`baseline` 또는 `candidate`)에서 실행한다. npm 설치 없이 Node 내장 모듈로 동작한다.

```powershell
# 로컬 화면. 종료는 Ctrl+C
node work/preview-prototype.cjs
# 브라우저에서 http://127.0.0.1:4173/ 열기

# 자동 테스트. 실패 시 즉시 중단
Get-ChildItem work/test-*.cjs | ForEach-Object {
  node $_.FullName
  if ($LASTEXITCODE -ne 0) { throw "테스트 실패: $($_.Name)" }
}

# 단일 HTML과 소스 폴더 생성
node work/package_prototype.cjs

# 배포용 소스 ZIP은 별도 생성
Compress-Archive -Path 'outputs/ORBIT-인터랙티브-시안' -DestinationPath 'outputs/ORBIT-인터랙티브-시안.zip' -Force
```

`test-day-view.cjs`는 소스 폴더에 `print-check.html` 시험 화면을 생성한다. 후보의 저장 테스트는 `work/storage-stress-results.json`을 생성한다. 테스트 후 소스 폴더 전체를 무조건 배포하지 말고 패키징 스크립트의 명시된 파일 목록을 사용한다. QA 전용 `quota-check.html`, `print-check.html`, 가짜 데이터 주입 스크립트는 운영 산출물에서 제외한다. 이번 묶음의 `baseline/`·`candidate/` 각 `work/travel-globe/dist/prototype/`에도 테스트 재실행으로 생긴 `print-check.html`이 남아 있고 `evidence/sha256.json`에 포함되어 있다. 소스 파일이 아니므로 코드 수정·배포 시 무시하거나 삭제한다.

이번 묶음의 `outputs/`는 동봉된 패키징 스크립트로 재생성했다. 원래 프로젝트의 과거 출력 파일과 바이트 단위로 같다는 의미는 아니다.

| test-storage-stability(후보) | 실패 시 되돌리기·손상 자료 보호·다른 탭 변경·대량 데이터 |

후보 대량 시험은 여행 100개·방문 10,000개·직접 장소 1,000개를 사용한다. Node의 가짜 DOM 환경에서 여는 동작·문자열 렌더링·재정렬·저장·백업 왕복을 확인했다. 기록된 밀리초 수치는 실제 모바일 성능이나 지도 프레임 속도를 뜻하지 않는다.

이전 대화에서 사용자가 Android의 한글 입력·직접 장소 추가·새로고침 유지·지도 전환·백업 다운로드 및 복원이 된다고 확인했다. 기기 모델·브라우저 버전·정확한 빌드 번호는 기록되지 않았다. iPhone 실기기 검증과 실제 PDF 저장 완료는 확인되지 않았다. 과거 작업기록의 ‘Android 미확인’과 ‘미배포’ 표현은 당시 상태이며 현재 모든 작업에 그대로 적용하면 안 된다.

## 10. 다음 할 일과 완료 기준

1. **버전 확정:** 기준/후보 차이를 리뷰하고 후보 브라우저 검증 완료. 백업을 확보한 뒤 원본·단일 HTML·소스 폴더·ZIP을 같은 버전으로 맞춘다.
2. **데이터 보존 보완:** 미배정 직접 장소 내보내기와 백업 한도 문제를 해결한다. 기존 백업·메모·복원 테스트를 모두 통과한다.
3. **인쇄 마감:** 실제 PDF 저장 후 긴 메모·일자별 페이지 나눔·메모 제외 옵션을 눈으로 확인한다. 개인정보가 의도대로 제외되는지 점검한다.
4. **실기기 품질 기록:** 사용자의 Android 모델·브라우저를 기록하고 느린 네트워크와 많은 방문으로 시험한다. iPhone은 기기가 확보되면 별도 검증한다.
5. **실제 검색·길찾기 결정:** 후쿠오카부터 제공자·한글/일본어 검색 품질·지도 병용 조건·저장 허용 범위·비용 상한을 비교해 사용자와 결정한다. 결정 전 유료 계정·API 연결을 진행하지 않는다.
6. **실제 데이터 연결:** 검색 → 좌표 확인 → 도보 경로 → 시간표·숙소 순으로 진행한다. 조회 실패를 0분이나 정상 경로로 표현하지 않는다.
7. **계정·동기화·공유:** 필요성과 비용을 결정한 뒤 별도 설계한다. 접근 권한·동시 수정·이관 중복·공유 링크 폐기·숙소와 메모 공개 범위 시험이 필요하다.

기존 개발실행계획서의 8주 일정은 당시 가정이며 현재 약속된 일정이 아니다. 예산·담당자·실제 API 제공자·베타 출시일은 미정이다. 모바일 개선·당일 보기·인쇄 화면은 이미 구현됐으므로 새로 만드는 작업과 남은 검증을 구분한다.

## 11. 배포·운영 인계

기록된 Sites 프로젝트 ID: `(비공개 처리)`. 로컬 체크아웃은 `orbit-site/`, 정적 파일은 `dist/index.html`, 설정은 `.openai/hosting.json`이다. 묶음에 인증 토큰·저장소 자격증명·사용자 여행 데이터는 넣지 않았다.

실제 배포 시에는 당시 설치된 Sites 스킬과 도구 안내를 새로 확인하고, 기존 프로젝트를 업데이트한다. 원격 현재 버전과 공개 범위를 확인하고 승인된 코드만 패키징한다. 배포 성공 상태와 게시 URL을 확인한 뒤 휴대전화에서 새로고침·생성·편집·백업을 재검증하고 배포 버전·날짜·코드 해시를 기록한다. 예전 도구 자격증명을 재사용하거나 문서에 기록하지 않는다.

웹 앱의 공개와 사용자의 일정 공유는 별개다. 현재 앱 코드는 공개 주소로 제공되지만 여행은 해당 브라우저 안에 저장된다. 주소를 바꾸면 예전 데이터가 사라진 것처럼 보일 수 있으므로 주소 변경 전 백업·복원 경로를 안내한다. 브라우저 데이터 초기화나 localStorage 전체 삭제를 복구 방법으로 먼저 제시하지 않는다.

## 13. 산출물 확인

코드의 각 파일 해시는 `evidence/sha256.json`에 기록했다. ZIP을 전달한 뒤 파일이 동일한지 비교할 수 있다. `reference/`의 과거 기획 문서는 배경 자료이며, 현재 구현 상태는 이 문서의 버전 구분·검증 현황과 코드를 우선한다. `sources/` 동기화 참고 자료와 원본 프로젝트 파일은 이번 작업에서 수정하지 않았다.
