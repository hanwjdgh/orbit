# 스펙: 외부 지도 연동 (키·서버 없이)

작성일: 2026-11-15 · 상태: 초안, 결정 대기 항목 있음

## 목표

API 키·서버 없이 실제 이동 정보를 일정에 반영한다. 사용자는 Google 지도에서 경로를 확인하고, ORBIT에는 위치와 이동시간만 옮겨 적는다.

- **A. 구간 길찾기 링크**: 연속한 두 방문 사이마다 Google 지도 길찾기를 연다.
- **B. 이동시간 직접 입력**: 구간 시간을 분 단위로 입력하면 시간표에 반영한다.
- **C. 위치 등록**: 직접 추가 장소에 지도 링크나 좌표를 붙여 넣어 지도 핀을 만든다.

범위 밖: 숙소 출발·복귀 구간, 단축 링크(`maps.app.goo.gl`) 해석, 직선 거리 추정, Apple 지도, 실시간 API.

## A. 구간 길찾기 링크

- 일정 편집과 시간표의 구간 줄(`leg`)에 "길찾기 ↗" 링크를 둔다. 새 탭으로 열고 `rel="noopener noreferrer"`를 붙인다.
- URL: `https://www.google.com/maps/dir/?api=1&origin=<출발>&destination=<도착>&travelmode=<walking|transit>`
  - 이동수단은 그날의 `mode`를 따른다(walk → walking, transit → transit).
  - 좌표가 있으면 `위도,경도`, 없으면 `이름 주소` 텍스트를 넣는다. 둘 다 `encodeURIComponent`로 처리한다.
- 같은 장소를 연속으로 방문한 구간(출발과 도착이 같은 좌표)에는 링크를 두지 않는다.

## B. 이동시간 직접 입력

**저장 위치**: 각 날짜에 `legs` 객체를 둔다. 키는 `<mode>:<앞 방문 uid>><뒤 방문 uid>`, 값은 0~1440의 정수 분이다.

```js
day.legs = { 'walk:v1>v2': 25, 'transit:v2>v3': 12 }
```

- 방문 순서를 바꾸거나 날짜를 옮기거나 방문을 삭제하면 키가 맞지 않게 되어 해당 구간이 자동으로 미입력이 된다. 무효화 코드를 따로 두지 않는다.
- 이동수단을 바꾸면 그 수단으로 입력한 값만 쓰인다.
- 저장할 때 현재 인접 구간에 해당하지 않는 키는 지운다(데이터가 계속 쌓이지 않게).

**시간표 계산** (`buildTimeline`): 구간 값은 다음 순서로 정한다.
1. 직접 입력값이 있으면 그 값을 쓴다. 표시: "도보 25분 · 직접 입력"
2. 없으면 **[결정 1]** 에 따른다.

**입력 UI**: 시간표 화면의 구간 줄에 "시간 입력" 버튼을 둔다. 누르면 숫자 입력칸(분)과 저장·지우기 버튼이 그 자리에 열린다. 저장에 실패하면 기존 패턴대로 이전 값을 유지하고 안내한다.

**내보내기·인쇄**: 텍스트 내보내기와 인쇄 화면의 구간에 "도보 25분 (직접 입력)" 또는 "이동시간 미확인"을 표시한다.

## C. 위치 등록

**입력 위치**
- 직접 장소 추가 창에 "지도 링크 또는 좌표 (선택)" 칸을 추가한다.
- 기존 직접 장소의 상세 창에 같은 칸과 "위치 저장"·"위치 지우기" 버튼을 둔다.

**해석 규칙** (`parseLocation(text)` → `[경도, 위도]` 또는 오류). 앞에서부터 처음 맞는 것을 쓴다.
1. `!3d<위도>!4d<경도>`: Google 장소 링크의 실제 장소 좌표
2. `@<위도>,<경도>`: Google 지도 화면 중심(장소와 조금 다를 수 있음)
3. `q=`, `query=`, `ll=` 파라미터의 `<위도>,<경도>`
4. 숫자만 있는 `<위도>, <경도>`

- 위도는 -90~90, 경도는 -180~180이어야 한다.
- 여행 도시 중심에서 50km보다 멀면 저장은 허용하되 "도시와 멀리 떨어진 위치입니다" 경고를 띄운다.
- 단축 링크이거나 해석에 실패하면 "브라우저에서 연 긴 지도 주소를 복사하거나 위도, 경도를 입력해 주세요"라고 안내하고 저장하지 않는다.

**저장과 표시**
- 직접 장소에 선택 필드 `coord: [경도, 위도]`를 둔다. 예시 장소와 같은 순서다.
- `resolvePlace`·`indexedPlace`는 `coord`가 있으면 그대로 쓴다. 이 경우 "위치 미등록" 표시를 하지 않는다.
- 지도 핀은 예시 장소 외에 좌표가 있는 직접 장소도 표시한다. 연결선은 기존 `routeFeatures`를 그대로 쓴다.

## 백업 호환

- 새 백업은 `version: 2`로 쓴다. 읽을 때는 1과 2를 모두 받는다.
- 이전 앱은 version 2 파일을 "지원하지 않는 버전"으로 거부한다. 좌표와 이동시간이 조용히 사라지는 것을 막기 위해서다.
- 검증 규칙
  - `coord`: 숫자 2개, 범위 검사
  - `legs`: 객체, 키 형식 `^(walk|transit):[A-Za-z0-9-]+>[A-Za-z0-9-]+$`, 값은 0~1440 정수, 날짜별 키 수는 방문 수 × 2 이하
- 복원할 때는 방문 uid를 새로 발급하므로 `legs` 키도 새 uid로 바꿔 쓴다(`appendBackup`).

## 결정 필요

1. **입력하지 않은 구간의 표시**
   - (권장) "미확인"으로 표시한다. 실제로 쓰기 시작하면 가짜 예시값이 오해를 낳는다. 그 구간 이후의 시간표는 지금의 실패 시나리오처럼 미확인이 된다.
   - 또는 지금처럼 "시안 예시" 값을 유지한다.
2. **시간표의 "조회 실패 예시" 시나리오 선택**: 1에서 "미확인"을 고르면 이 시연용 옵션은 필요 없으니 제거를 권장한다.

## 검증

- 단위 테스트
  - `parseLocation`: 위 4가지 형식, 단축 링크, 범위 밖 값, 공백·한글이 섞인 입력
  - `buildTimeline`: 입력값 반영, 순서 변경 후 미입력 처리, 이동수단별 분리
  - 백업: v2 왕복, v1 읽기 호환, 잘못된 `coord`·`legs` 거부, 복원 시 `legs` 키 재발급
  - 텍스트 내보내기·인쇄: 구간 시간 표시
- 브라우저 확인
  - 길찾기 링크가 맞는 출발·도착·이동수단으로 열리는지
  - 직접 장소 핀이 지도에 나타나는지
  - 320px 화면에서 구간 줄과 입력칸이 화면을 넘지 않는지
